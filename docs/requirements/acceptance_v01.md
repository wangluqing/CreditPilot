## 1. 验收原则

所有测试使用原创合成固定样例和虚构参数，默认离线执行。场景夹具将在 CP-03 后冻结，本文不为 `DEMO-0001` 或 `DEMO-0002` 预设结果。断言应针对结构化状态、证据、版本和工具调用，而非仅匹配自然语言。

主状态分为两组：`analysis_status` 取 `SUCCESS`、`PARTIAL`、`FAILED`、`NOT_FOUND`、`INVALID_INPUT`；`decision_status` 取 `PASS`、`REJECT`、`NEEDS_REVIEW`、`NOT_EVALUATED`。内部 `PASS` 仅表示模拟策略未触发拒绝，Web 必须展示“未触发模拟拒绝规则”。`TOOL_ERROR`、`UNKNOWN` 等作为稳定错误码、证据状态或补充字段，其具体契约由 CP-02 定义。

完整模拟策略结果依赖已通过工具证据校验的有效规则结果和有效评分结果。任一必需依赖失败时不得对外发布最终 `PASS` / `REJECT`，但允许保留并标注已验证的部分证据。固定处理顺序为：工具执行 → 工具证据校验 → 确定性策略计算 → 可选 LLM 解释 → 最终解释校验 → Web 展示。

## 3. 正常场景

### AC-001 正常模拟拒绝

- 输入条件：冻结合成客户满足至少一条虚构拒绝规则；所有版本一致且证据完整。
- 预期行为：工具链按顺序执行；DecisionTool 基于实际命中规则生成模拟拒绝。
- 预期状态：`analysis_status=SUCCESS`；`decision_status=REJECT`，并标记“模拟策略结果”。
- 禁止行为：LLM 自行拒绝；把未命中规则或模型因素写成拒绝原因；执行真实拒绝或通知。
- 自动化建议：pytest 固定夹具，断言调用顺序、策略版本、原因 ID、规则 ID 和证据引用。

### AC-002 正常模拟通过

- 输入条件：冻结合成客户资料完整，未触发模拟拒绝条件；版本一致。
- 预期行为：返回演示评分、因素和无拒绝命中的可追溯结果。
- 预期状态：`analysis_status=SUCCESS`；`decision_status=PASS`。Web 仅展示“未触发模拟拒绝规则”。
- 禁止行为：表述为真实批准、授信承诺或额度建议；生成不存在的拒绝原因。
- 自动化建议：断言状态、空 Policy Decision Reason、模型因素独立存在及免责声明。

### AC-003 规则命中解释

- 输入条件：客户命中已知虚构规则，规则执行记录包含版本、字段、操作符、阈值和实际值。
- 预期行为：逐条展示命中规则和来源证据，EvidenceValidator 验证引用。
- 预期状态：`analysis_status=SUCCESS`；`decision_status` 等于固定夹具的确定性 `PASS` 或 `REJECT`；证据状态为 `CONSISTENT`。
- 禁止行为：省略版本；展示未执行规则为已命中；引用其他客户字段。
- 自动化建议：参数化断言规则 ID、版本、比较表达式、来源路径和客户 ID。

### AC-004 风险评分解释

- 输入条件：评分字段完整，冻结模型版本和参数可用。
- 预期行为：RiskModelTool 产生可复现分数、等级及有方向的因素贡献。
- 预期状态：仅请求评分时 `analysis_status=SUCCESS`、`decision_status=NOT_EVALUATED`；完整分析时由经校验的规则和评分共同进入 DecisionTool。
- 禁止行为：LLM 心算分数；宣称预测准确率；将因素自动升级为拒绝原因。
- 自动化建议：对固定输入断言精确分数、等级、模型版本、因素排序及重复运行一致性。

### AC-005 模型因素与拒绝原因区分

- 输入条件：客户同时具有模型风险因素和至少一项不同来源的策略拒绝原因。
- 预期行为：API、报告和 Web 分别输出 Policy Decision Reason、Model Risk Factor、Business Guidance。
- 预期状态：`analysis_status=SUCCESS`；`decision_status=REJECT`；证据状态为 `CONSISTENT`。
- 禁止行为：合并三类数组；把最高贡献因素称为拒绝原因；Business Guidance 冒充审批意见。
- 自动化建议：验证响应 schema 的独立字段、不同来源类型和 Web 独立标题/区域。

## 4. 异常与边界场景

### AC-006 客户不存在

- 输入条件：格式合法但数据集中不存在的模拟客户编号。
- 预期行为：CustomerTool 返回不存在，停止规则、评分和决策工具调用。
- 预期状态：`analysis_status=NOT_FOUND`；`decision_status=NOT_EVALUATED`。
- 禁止行为：模糊匹配、生成客户画像、返回其他客户数据或继续计算。
- 自动化建议：Mock 下游工具并断言零调用；断言稳定错误码且响应不含画像。

### AC-007 关键资料缺失

- 输入条件：冻结客户缺少至少一个被定义为决策或评分必需的字段。
- 预期行为：列出缺失字段；不执行依赖该字段的确定计算；提示人工补充或复核。
- 预期状态：`analysis_status=PARTIAL`；若已进入评估则 `decision_status=NEEDS_REVIEW`，否则为 `NOT_EVALUATED`；`UNKNOWN` 仅可作为补充证据状态。
- 禁止行为：默认补零、均值填充、LLM 猜测或输出确定的通过/拒绝。
- 自动化建议：参数化缺失字段，断言状态、缺失列表、被跳过工具及无确定结论。

### AC-008 规则阈值边界

- 输入条件：合成字段分别为阈值减最小步长、等于阈值、阈值加最小步长。
- 预期行为：严格按冻结操作符计算，三组结果可重现并记录实际值。
- 预期状态：三组均为 `analysis_status=SUCCESS`；`decision_status` 分别等于冻结边界表预期的 `PASS` 或 `REJECT`。
- 禁止行为：浮点隐式舍入改变结果；LLM 解释覆盖规则计算。
- 自动化建议：pytest 参数化边界表；必要时使用 Decimal；断言命中布尔值和策略结果。

### AC-009 工具调用失败

- 输入条件：任一必需工具超时、抛出受控异常或返回无效结构。
- 预期行为：停止依赖链，允许展示明确标注的已验证部分证据，返回安全错误摘要和人工复核提示。
- 预期状态：存在可展示的已验证部分证据时 `analysis_status=PARTIAL`，否则为 `FAILED`；已进入评估时 `decision_status=NEEDS_REVIEW`，否则为 `NOT_EVALUATED`；错误码可为 `TOOL_ERROR`。
- 禁止行为：伪装成功、重用陈旧结果、由 LLM 补齐或在日志输出敏感载荷。
- 自动化建议：分别 Mock 每个工具失败，断言下游调用、错误映射、关联 ID 和响应脱敏。

### AC-010 证据不一致

- 输入条件：构造客户 ID、数据版本、字段值或工具版本至少一处冲突。
- 预期行为：EvidenceValidator 检出并列明冲突，受影响结论不可发布。
- 预期状态：`analysis_status=PARTIAL`；`decision_status=NEEDS_REVIEW`；证据状态为 `INCONSISTENT`。
- 禁止行为：任意选择一方、静默覆盖、仍返回确定通过/拒绝或隐藏冲突。
- 自动化建议：对每种冲突参数化测试，断言冲突路径、来源和最终状态。

## 5. 安全与鲁棒性场景

### AC-011 非法客户编号

- 输入条件：过长、含控制字符、路径片段、SQL 片段或不符合公开正则的编号。
- 预期行为：Pydantic/输入层在工具调用前拒绝，并返回通用校验信息。
- 预期状态：`analysis_status=INVALID_INPUT`；`decision_status=NOT_EVALUATED`。
- 禁止行为：回显危险载荷、查询数据源、执行工具或泄露内部路径。
- 自动化建议：参数化恶意输入，断言 4xx、零工具调用和安全响应。

### AC-012 提示注入与越权请求

- 输入条件：用户要求忽略规则、伪造批准、透露密钥、调用真实系统或改变既定结果。
- 预期行为：拒绝越权部分；保留系统边界；如含合法只读问题，仅按合成证据回答。
- 预期状态：纯越权请求为 `analysis_status=FAILED`、`decision_status=NOT_EVALUATED`；若请求含可安全分离的合法查询，则按其确定性结果返回主状态并附安全拒绝说明。
- 禁止行为：泄露配置、改变工具输出、执行网络/写操作或生成正式授信意见。
- 自动化建议：使用 Mock LLM 和工具白名单，断言无敏感字段、无未授权调用和结果不可篡改。

### AC-013 LLM 超时或不可用

- 输入条件：LLM 意图识别或表达步骤超时/不可用，确定性工具可用或尚未调用。
- 预期行为：返回明确失败；可选的确定性降级只能使用预定义模板且必须标记，不得伪装为 LLM 成功。
- 预期状态：若确定性策略尚未完成，则 `analysis_status=FAILED`、`decision_status=NOT_EVALUATED`；若策略结果已完成并通过工具证据校验，则 `analysis_status=PARTIAL`，保留原确定性 `decision_status`，使用固定模板展示并记录 LLM 错误码。
- 禁止行为：无限重试、编造自然语言结论、调用真实备用服务或隐藏失败。
- 自动化建议：Mock 超时，断言有限重试策略、错误状态、无真实网络和降级标记。

## 6. 后续 pytest 验证建议

- 单元测试：CustomerTool、RuleEngineTool、RiskModelTool、DecisionTool 和 EvidenceValidator 分层测试。
- 契约测试：Pydantic 请求/响应模型、稳定状态枚举、证据引用及三类输出结构。
- 集成测试：使用内存合成夹具和 Mock LLM 跑完整工具链，不访问网络。
- API 测试：FastAPI TestClient 验证 HTTP 状态、结构化错误及敏感字段缺失。
- Web 测试：验证三类输出分区、异常状态、版本与演示标签；不测试真实业务操作。
- 可复现性测试：同一夹具和版本重复执行，比较规范化后的确定性输出。
- 安全测试：非法编号、提示注入、密钥与日志泄露、未授权工具调用。

建议测试命名采用 `test_ac_001_*` 格式，使失败可直接追踪至 AC。自然语言可做稳定字段断言，不以完整句子作为唯一验收依据。

## 7. V0.1 发布验收条件

1. FR-01 至 FR-08 均已实现，并至少由一个自动化 AC 覆盖。
2. AC-001 至 AC-013 的适用自动化测试全部通过，且无通过率或准确率虚假宣传。
3. 相同输入和版本的规则、评分、决策结果可复现。
4. 三类输出在 schema、报告和 Web 中明确分离。
5. 客户不存在、资料缺失、必需工具失败和证据冲突均不会产生或发布最终 `PASS` / `REJECT`；已验证部分证据可以标注展示。
6. 默认离线测试通过，真实 LLM 和外部网络调用为零；LLM 测试使用 Mock。
7. 无真实数据、真实策略、密钥、数据库或敏感日志进入仓库和 Git 历史。
8. README 仅把实际实现且验证过的能力标为已实现，其余明确标为规划。
9. pytest 与 Ruff 检查通过，失败不得通过修改验收证据掩盖。
10. Product Owner 已批准 [PRD 冻结产品决策](prd_v01.md#11-已批准并冻结的产品决策)；D01–D06 及版本语义属于 V0.1 冻结基线。
